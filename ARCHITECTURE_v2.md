7 августа 2026 · пересборка v1.0 после проверки критики по данным публичного сета

## 0. Что изменилось и почему

Версия 1.0 была выведена из одного разобранного сценария (B1) и оказалась на нём переобучена.
Проверка остальных одиннадцати заёмщиков нашла четыре механики, которые v1.0 **физически
не способна выразить**, и два документа, которые она **молча удалила бы**.

### Верифицированные дефекты v1.0

| # | Дефект | Доказательство в публичных данных |
|---|---|---|
| 1 | `CovenantSpec` не выражает вложенные операции | P10 6.2: «Выручка за вычетом **наибольшей из** Расходов на оплату труда **и** Налогов» = `subtract(sum, max(sum, sum))`. Плоское поле `aggregation: sum\|max` этого не кодирует |
| 2 | Нет условий применимости | P3 6.1: ограничение 1.70x «применяется **только при условии**, что совокупные поступления по финансированию превышают $4,000,000.00». Springing test |
| 3 | Нет оговорок-исключений | P7 6.3: «**За исключением случаев**, прямо согласованных Кредитором в письменной форме…» |
| 4 | Нет фактов из документов, только транзакции | P7 6.1: «Начисленные, но не уплаченные налоги учитываются наравне с уплаченными; их величина подтверждается **учётными данными казначейства**» |
| 5 | Триаж удаляет всё без известных маркеров | `26acfab1e58b` — служебная записка казначейства. Ни договор, ни аудит, ни KYC. v1.0 помечает `noise` и выбрасывает |
| 6 | Нет чтения PDF без текстового слоя | `f3fa6d20c8a1` — **KYC-досье P6, чистая картинка**, 0 шрифтов, 0 символов. Без vision у P6 ковенант 6.3 нерешаем |
| 7 | Порог связанных сторон захардкожен по смыслу | B1: «20.0% и более». P6: «**40.0% и более**». Taraz Kiln Services 38.1% — под порогом |
| 8 | Нормализация ломает обычный текст | `re.sub(r"(?<=\w) (?=\w(?: \|$))", ...)` даёт «средстваи», «Налогови», «2025-12-31в» — и при этом целевую строку не чинит: остаётся `ACC - 7201` |
| 9 | Sanity-диапазоны как hard-блокеры | Нарушение эвристики заменяло, возможно, верный ответ гарантированно слабым baseline |
| 10 | Занижен счёт вызовов | В §9 написано «12 вызовов», в таймбюджете — 36. Верно 36; прямая нестыковка |

### Дефект, которого не нашёл ни один разбор

**В леджере есть транзакции с пустой суммой.**

```
TXN-P7-0033  2025-11-18  ACC-7807  State Revenue Committee           amount = NaN
TXN-P8-0031  2025-12-04  ACC-7808  Kyzylorda Drilling Personnel LLP  amount = NaN
```

Истинные суммы лежат в документах:

- `$486,204.19` — служебная записка казначейства `26acfab1e58b`, раздел «Позиции, не выгруженные в бухгалтерскую выгрузку». **Документ вне всех известных типов.**
- `$884,204.16` — аудиторское дело `bf9b7bffc514`, «Примечание 8 — Суммы, не отражённые в выгрузке реестра».

Обе транзакции участвуют в ковенантах (`TXN-P7-0033` — налоги, входят в числитель P7 6.1;
`TXN-P8-0031` — выплата контрагенту с долей 36.2%). `pandas` прочитает их как `NaN`, сумма
молча даст неверный результат, и никакой валидатор этого не поймает.

**Отсюда — смена направления поиска.** v1.0 шла от документов к леджеру: классифицировать
PDF, извлечь корректировки, применить. Этого недостаточно, потому что нужный документ
может не иметь ни одного знакомого маркера. v2.0 добавляет обратный ход: **найти пробелы
в леджере, затем искать их номера транзакций по всему корпусу.** Это детерминированно,
не зависит от типа документа и находит оба случая.

## 1. Разбор критики: что принято и что нет

| Пункт | Вердикт | Комментарий |
|---|---|---|
| 1. `CovenantSpec` слишком узкий | **Принято, недооценено** | Он привёл выдуманный пример про взносы акционеров. Реальные случаи хуже: вложенный `max` внутри вычитания вообще невыразим. Но его решение (плоские `applicability_condition: str`) слабое — строка не исполняется. Нужно бounded-дерево выражений |
| 2. Evidence resolver слишком узкий | **Принято** | Пул кандидатов вместо только корректировок — верно. Пять типов контрфактов избыточны, хватает трёх |
| 3. Число вызовов занижено | **Принято** | У меня прямая нестыковка 12 против 36. Один SELECT на сценарий — правильно и по бюджету, и по кешу |
| 4. Нужен OCR/vision fallback | **Принято, недооценено** | Он предлагал как страховку. Это **обязательное**: без него один из двенадцати KYC не читается вообще |
| 5. Нормализация слишком общая | **Принято** | Проверил — мой regex действительно калечит русский текст и не решает целевую задачу |
| 6. Hard и soft проверки смешаны | **Принято** | Замена вероятно верного ответа на baseline — потеря 0.5 балла на ровном месте |
| 7. Версии не только по году | **Принято** | Плюс P10 6.1: «реклассификации, **рассмотренные и отклонённые** аудиторами, в расчёт не принимаются» — отклонённые кандидаты обязаны храниться, а не удаляться |
| 8. `unknown → amount` опасен | **Принято частично** | Диагноз верный. Лечение — нет: он предлагает при `unsupported` не отвечать уверенно. Но по правилам **пустая и неверная ячейка стоят одинаково**, значит отвечать надо всегда. Правильно: считать по ограниченному плану + `low_confidence`, а не воздерживаться |
| Provenance до страницы и цитаты | **Принято** | Дёшево, резко ускоряет разбор low-confidence |
| `DocumentFact` как общий объект | **Принято, недооценено** | Он предполагал, что «пригодится». P7 6.1 без этого не решается вообще |

Ничего не отклонено полностью. Скорректированы два решения из восьми.

## 2. Модели данных v2.0

### 2.1 Выражения — ограниченное дерево вместо плоских полей

Восемь операций, не больше. Это не язык программирования: рекурсия ограничена глубиной 4,
исполнитель — `match`-конструкция на сорок строк.

```python
Op = Literal["sum", "add", "subtract", "divide", "max", "min", "const", "fact"]

class Expr(BaseModel):
    op: Op
    role: str | None = None          # для sum: имя роли, транзакции берёт SELECT
    fact_name: str | None = None     # для fact: ссылка на DocumentFact
    value: Decimal | None = None     # для const
    args: list["Expr"] = []          # для add/subtract/divide/max/min
```

Все реальные ковенанты публичного сета выражаются:

```python
# B1 6.1  ICR = (Выручка − Опекс) / Проценты
divide(subtract(sum("revenue"), sum("opex")), sum("interest"))

# B1 6.2  максимум из двух статей накладных
max(sum("payroll"), sum("utilities"))

# B1 6.3  платежи связанным сторонам
sum("related_party")

# P10 6.2 Выручка − наибольшая из (оплата труда, налоги)   ← v1.0 невыразимо
subtract(sum("revenue"), max(sum("payroll"), sum("taxes")))

# P10 6.3 доля связанных сторон в выручке
divide(sum("related_party"), sum("revenue"))

# P7 6.1  (Налоги + Коммунальные) / EBITDA, налоги включают начисленные
divide(add(sum("taxes"), sum("utilities")), sum("ebitda"))
```

### 2.2 Ковенант

```python
class CovenantSpec(BaseModel):
    scenario_id: str
    clause_id: str

    value_expr: Expr                     # то, что идёт в actual
    operator: Literal["<=", ">=", "<", ">"]
    threshold: Decimal

    # Springing / условная применимость (P3 6.1)
    applicability: Condition | None = None
    # Оговорка-исключение (P7 6.3)
    exception: Condition | None = None

    period_start: date
    period_end: date
    role_descriptions: dict[str, str]    # дословно из текста, уходит в SELECT
    uses_related_parties: bool
    supported: bool = True               # False -> low_confidence, но ответ всё равно даём
    source: SourceRef


class Condition(BaseModel):
    expr: Expr
    operator: Literal["<=", ">=", "<", ">", "=="]
    threshold: Decimal
    raw_text: str                        # для верификатора и трейса
```

**Семантика статуса — ключевое отличие от v1.0:**

```python
actual = evaluate(spec.value_expr)          # считается ВСЕГДА

if spec.applicability and not holds(spec.applicability):
    status = "COMPLIANT"                    # ковенант не применяется
elif spec.exception and holds(spec.exception):
    status = "COMPLIANT"                    # сработала оговорка
else:
    status = "COMPLIANT" if compare(actual, spec.operator, spec.threshold) else "BREACH"
```

`actual` — всегда фактическое значение показателя, а не значение условия, и оно может быть
выше лимита при `COMPLIANT`. Это прямое требование CASE.md, которое v1.0 нарушала.

### Стадия 2 — PDF extract с vision-фоллбэком

```python
import fitz

def extract_text(path: str) -> tuple[str, str]:
    doc = fitz.open(path)
    text = "\n".join(p.get_text() for p in doc)
    if len(text.strip()) < 200:
        pages = [p.get_pixmap(matrix=fitz.Matrix(2, 2)) for p in doc[:3]]
        return vision_extract(pages), "vision"
    return text, "text"
```

PyMuPDF обрабатывает весь корпус одной библиотекой, без `subprocess`, и корректно работает
с Unicode-путями Windows. Порог `< 200` проверен на публичном сете: единственный скан
`f3fa6d20c8a1` даёт 0 символов, ближайший нормальный документ — около 900. На публичном
сете vision-ветка срабатывает **ровно один раз** — для KYC P6. `fitz.Matrix(2, 2)` даёт
примерно 144 DPI; повышать масштаб до `Matrix(3, 3)` допустимо только при ошибках vision
на процентах, выше — не поднимать из-за стоимости.

### Стадия 3 — Триаж с целевой нормализацией

Нормализация точечная, а не сплошная:

```python
ACC_RE = re.compile(r"[AА]\s*[CС]\s*[CС]\s*[-–—]\s*(\d)\s*(\d)\s*(\d)\s*(\d)")
REP_RE = re.compile(r"A\s*R\s*[-–—]\s*(\d)\s*(\d)\s*(\d)\s*(\d)\s*[-–—]\s*(\d)\s*(\d)\s*(\d)\s*(\d)")
TXN_RE = re.compile(r"T\s*X\s*N\s*[-–—]\s*([A-Z0-9]+)\s*[-–—]\s*(\d+)")

def normalize_identifiers(text: str) -> str:
    text = unicodedata.normalize("NFKC", text)
    text = ACC_RE.sub(lambda m: "ACC-" + "".join(m.groups()), text)
    text = REP_RE.sub(lambda m: "AR-" + "".join(m.groups()[:4]) + "-" + "".join(m.groups()[4:]), text)
    text = TXN_RE.sub(lambda m: f"TXN-{m.group(1)}-{m.group(2)}", text)
    return text
```

Латиница и кириллица в классах символов — потому что в PDF `А` может быть русской.
Остальной текст не трогается вообще.

Маркер задаёт только **кандидата**, а не окончательный тип. На публичном корпусе фразу
«Знай своего клиента» содержат 18 документов, включая процедуры обновления KYC, а заголовок
договора встречается в 24 документах, включая недействующие редакции. Для ранжирования типа
нужны одновременно: маркер, наличие `ACC-XXXX` и сигналы версии; окончательное разрешение
версии выполняет стадия 4. Стадия 3 сохраняет все кандидаты и их сигналы, не вызывает LLM и
не удаляет документы. `noise` означает только «не попадает в контекст стадии 6».

### Стадия 4 — Граф версий

Приоритет разрешения, в порядке применения:

1. `version_status == "draft"` — исключается из применения, но **остаётся в графе**
   как `rejected_candidate` с причиной. P10 6.1 прямо требует отличать отклонённые
   реклассификации от несуществующих.
2. Явная связь `superseded_by` / ссылка по `report_number`.
3. `effective_date`, затем `signed_date`, затем `fiscal_year`.
4. Не разрешилось — `low_confidence`, берётся первый кандидат, решение логируется.

### Стадия 6 — Extract, один вызов на сценарий

Объединено по рекомендации: вместо трёх вызовов на заёмщика — один на весь разрешённый
комплект. Вход: Статья 6 + аудит-цепочка + KYC + найденные на стадии 5 фрагменты.
Это ~10 КБ, комфортно для окна и **позволяет модели связать перекрёстные ссылки**
(«величина подтверждается учётными данными казначейства» → искать в приложенной записке).

Выход: `CovenantSpec[]`, `Adjustment[]`, `RelatedParty[]`, `DocumentFact[]`, все с `SourceRef`
и дословной цитатой.

**Детерминированные стражи поверх выхода модели** — компенсация за слабую модель:

```python
if re.search(r"не допуска\w+ снижени|не менее|не ниже", clause):   forced = ">="
if re.search(r"не должн\w+ превышать|не более|не выше",   clause):  forced = "<="
if re.search(r"наибольш|не является показателем|по отдельности, а не в совокупности", clause):
    require_max_node(spec.value_expr)
if re.search(r"только при условии|применяется, если", clause):
    require(spec.applicability is not None)
if re.search(r"за исключением случаев", clause):
    require(spec.exception is not None)
```

Расхождение стража с моделью — `soft_warning` и маршрут в верификатор, не молчаливая правка.

### Стадия 7 — Select, один вызов на сценарий

Вход: три `CovenantSpec` с `role_descriptions`, полный срез счёта (~57 строк), список
связанных сторон, список корректировок. Выход — только идентификаторы:

```json
{
  "6.1": {"revenue": ["TXN-B1-0026"], "opex": ["TXN-B1-0023"], "interest": ["TXN-B1-0033"]},
  "6.2": {"payroll": ["TXN-B1-0004"], "utilities": ["TXN-B1-0014"]},
  "6.3": {"related_party": ["TXN-B1-0030"]}
}
```

В системном промпте обязательная строка: *«Рассматривай каждый пункт независимо.
Не переноси выбранные категории между пунктами.»*

Риск склейки трёх ковенантов в одном вызове на Haiku реален. Поэтому режим —
переключаемый флагом `SELECT_MODE=scenario|covenant`, и **какой лучше, решает замер
на local scorer**, а не рассуждение. Бюджет по умолчанию: `scenario`.

### Стадия 9 — Evidence, ограниченный пул

```python
if base_status == "COMPLIANT":
    return None

candidates = unique(
    [m.txn_id for m in all_adjustment_matches]      # реклассификации, cutoff, коррекции сумм
    + boundary_related_parties                       # доли в пределах ±5 п.п. от порога
    + fx_converted_txn_ids                           # операции в валюте
)                                                    # обычно 1–6, не 57

flippers = []
for txn in candidates:
    for cf in (drop_txn, revert_adjustment, flip_related_party_status):
        if cf.applicable(txn) and recompute(cf.apply(txn)).status != base_status:
            flippers.append(txn); break
return flippers[0] if len(flippers) == 1 else None
```

Три типа контрфакта вместо пяти: удаление, откат корректировки, смена статуса связанной
стороны. Остальные два из разбора сводятся к первым двум.

`COMPLIANT → null` — правило по определению задачи (доказательство требуется, когда
нарушение вызвано конкретной операцией), подкреплённое распределением ключа: 0 из 19.

## 6. Что осталось из v1.0 без изменений

Эти решения проверку выдержали и не пересматриваются:

- Workflow вместо автономного агента; поток управления в коде.
- Ни одно число в `submission.json` не приходит из модели; SELECT возвращает только `txn_id`.
- Baseline-сабмит с первой минуты, атомарная перезапись после каждой ячейки.
- Никакого глобального классификатора транзакций — категории задаёт текст ковенанта.
- Никакого vector DB, LangGraph, multi-agent, fine-tuning, LLM-as-judge.
- Состав задачи читается из шаблона; номера пунктов ничего не означают.
- Eval harness переносится из higgsfield: runner, scorer, diff, traces, viewer, repeats.
- Приоритет по деньгам: документ → порог → набор транзакций → знаки после запятой.

Пропорция сдвинулась с 20/80 к **~15% LLM / 85% кода**: стражи, граф версий, gap scan
и targeted retrieval — всё детерминированное.
