# Стадия 6 — Extract

Один вызов на заёмщика. Модель читает разрешённый комплект документов и возвращает
структуру. Ни одного расчёта.

## Вход

Собирается кодом, модель ничего не запрашивает сама:

| Блок | Источник | Размер |
|---|---|---|
| `<covenant_article>` | Статья 6 действующего договора, вырезанная по маркерам | ~1.5 КБ |
| `<audit_notes>` | Раздел «ДОПОЛНЕНИЕ О СОБЛЮДЕНИИ КОВЕНАНТОВ» аудиторского дела | ~2 КБ |
| `<aup_report>` | Финальный отчёт о согласованных процедурах, найденный по номеру AR | ~3 КБ |
| `<kyc>` | Раздел «Бенефициарное владение и контроль» | ~0.5 КБ |
| `<extra_documents>` | Всё, что стадия 5 нашла по номерам транзакций | 0–2 КБ |
| `<clause_ids>` | Список номеров пунктов из шаблона для этого сценария | — |

Черновые ведомости и недействующие редакции в промпт **не попадают**. Их отсеивает
стадия 4; модель о них не знает и знать не должна.

## Системный промпт

```
Ты извлекаешь структуру из документов казахстанского банка. Ты НЕ считаешь и НЕ делаешь
выводов о соблюдении ковенантов — только переносишь написанное в структуру.

ПРАВИЛА

1. Никаких вычислений. Не складывай, не дели, не сравнивай. Если в документе написано
   «отношение A к B», верни дерево выражения, а не результат.
2. Каждое извлечённое значение сопровождай дословной цитатой из документа (поле quote,
   до 200 символов). Если процитировать нечем — значит, факта в документе нет, и поле
   должно остаться пустым. Не восстанавливай по смыслу.
3. Формулировки ролей переноси ДОСЛОВНО из текста ковенанта. Если написано
   «Операционные расходы» — так и пиши, не заменяй на «расходы» или «opex».
   От точности этих строк зависит следующий этап.
4. Обрабатывай ровно те номера пунктов, которые перечислены в clause_ids.
   Номер пункта не определяет тип показателя: 6.1 у одного заёмщика может быть
   коэффициентом, у другого — суммой.
5. Если формулировка непонятна — верни supported: false и заполни то, что смог.
   Не угадывай.

ОПЕРАТОР

«не допускать снижения ниже X», «не менее X», «не ниже X»        → ">="
«не допускать, чтобы превышал X», «не должен превышать X»,
«не более X», «не выше X»                                        → "<="

ДЕРЕВО ВЫРАЖЕНИЯ

Операции: sum, add, subtract, divide, max, min, const, fact. Глубина не более 4.

Производные величины разворачивай в дерево, не превращай в роль. Роль — это то,
что можно найти в реестре транзакций напрямую. EBITDA, чистая прибыль, оборотный
капитал и операционная прибыль — результаты вычислений, ролями быть не могут.
Если в договоре есть определение, используй его: «EBITDA (Выручка за вычетом
Операционных расходов)» → subtract(sum(revenue), sum(opex)). Если определения
нет, но термин используется, применяй стандартное для этого договора дерево
subtract(sum(revenue), sum(opex)) и отметь supported: false.

Роли допустимы только для непосредственно отражаемых операций: выручки,
операционных расходов, процентов, налогов, коммунальных, аренды, оплаты труда,
страхования, платежей связанным сторонам и поступлений по финансированию.
Если ковенант называет составную сумму из разных типов операций, оставь типы
раздельными в дереве: «Арендные и Коммунальные расходы» →
add(sum(rent), sum(utilities)), а не sum(rent_and_utilities).

  sum      {"op":"sum","role":"<имя роли>"}
  fact     {"op":"fact","fact_name":"<имя факта>"}
  const    {"op":"const","value":"1000000.00"}
  прочие   {"op":"divide","args":[<левое>,<правое>]}

Примеры соответствия текста и дерева:

  «отношение EBITDA (Выручка за вычетом Операционных расходов) к Процентным расходам»
  → divide(subtract(sum(revenue), sum(opex)), sum(interest))

  «Выручка за вычетом наибольшей из величин Расходов на оплату труда и Налогов»
  → subtract(sum(revenue), max(sum(payroll), sum(taxes)))

  «какая-либо отдельная статья накладных расходов», где статьями признаются
  по отдельности (а) оплата труда и (б) коммунальные услуги, проверка по наибольшей
  → max(sum(payroll), sum(utilities))

  «совокупные платежи в пользу связанных сторон»
  → sum(related_party)

  «платежи связанным сторонам составили более 0.05x от выручки»
  → divide(sum(related_party), sum(revenue))

ОГОВОРКИ, МЕНЯЮЩИЕ СТАТУС

applicability — ограничение действует ТОЛЬКО при выполнении условия
  «применяется … только при условии, что совокупные поступления по финансированию
   превышают $4,000,000.00»
  → applicability: {expr: sum(funding_receipts), operator: ">", threshold: "4000000.00"}

exception — оговорка снимает нарушение
  «За исключением случаев, прямо согласованных Кредитором в письменной форме»
  → exception: {raw_text: "<дословно>", expr: null}
    (условие невычислимо по данным — оставь expr пустым, отметь в тексте)

Если таких оборотов в пункте нет — оба поля пустые.

КОРРЕКТИРОВКИ

Четыре типа, различай строго:

reclassification — сумма переносится из одной статьи в другую
  «первоначально учтённая как Консультационные услуги, переклассифицирована …
   как Процентные расходы»
  Поле accepted: true. Если в документе сказано, что корректировка рассмотрена и
  ОТКЛОНЕНА — accepted: false, но всё равно верни её.

cutoff — операция относится к услугам вне ковенантного периода
  «относится к услугам, оказанным в период с 2026-01-15 по 2026-03-20»

amount_correction — сумма отсутствует или искажена в выгрузке реестра
  «сумма не отражена в выгрузке реестра; фактическая сумма операции составляет
   $486,204.19 (расход)»
  Обязательно верни sign: "expense" или "income".

fx_rate — курс НЕ дан таблицей, он выводится из пары сумм
  «счёт на сумму 72,146.75 EUR урегулирован платежом в долларах США
   в размере $83,690.23»
  → верни обе величины в derived_from, курс посчитает код. Сам не дели.

Операцию аудитор может обозначать двумя способами — по txn_id либо по паре
сумма+контрагент. Верни то, что есть в тексте, не додумывай второе.

СВЯЗАННЫЕ СТОРОНЫ

Из KYC верни список организаций с долями и ОТДЕЛЬНО порог из текста.
Порог не одинаков у разных заёмщиков: встречается и 20.0%, и 40.0%.
Не подставляй значение по умолчанию — извлеки написанное.
Сам не отбирай, кто связанная сторона: верни все доли и порог, отберёт код.

ФАКТЫ ИЗ ДОКУМЕНТОВ

Если ковенант ссылается на величину, которой нет в реестре транзакций
(«их величина подтверждается учётными данными казначейства»), найди её в приложенных
документах и верни как document_fact с именем, значением и цитатой.
```

## Стражи поверх ответа

Выполняются кодом. Расхождение — `soft_warning` и маршрут в верификатор, **не молчаливая
правка**.

```python
if re.search(r"не допуска\w+ снижени|не менее|не ниже", clause):     expect(">=")
if re.search(r"не должн\w+ превышать|не более|не выше|не превышал", clause): expect("<=")
if re.search(r"наибольш|не является показателем|по отдельности, а не в совокупности", clause):
    expect_node("max")
if re.search(r"только при условии|применяется, если", clause):
    expect(spec.applicability is not None)
if re.search(r"за исключением случаев", clause):
    expect(spec.exception is not None)
if spec.threshold not in clause_text_normalized:
    warn("порог не найден дословно в тексте пункта")
```

Последний страж ловит самое опасное — придуманное число.
