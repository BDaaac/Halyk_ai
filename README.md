# Halyk AI Challenge — пайплайн проверки кредитных ковенантов

Решение читает структуру задания из `submission_template.json`, читает грязные
финансовые документы и реестр транзакций, и для каждой пары (заёмщик, пункт
ковенанта) возвращает `status`, `actual` и `evidence_txn_id`. **Ни одно число в
итоговом `submission.json` не приходит от модели** — LLM возвращает только
идентификаторы транзакций, дерево выражений и дословные цитаты, а суммы и
коэффициенты считает Python из CSV.

Текущий балл на публичном сете: **0.9000** (34 из 36 статусов, evidence и
допуски по значениям).

## Запуск в три команды

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env    # затем впишите ANTHROPIC_API_KEY
.\.venv\Scripts\python.exe main.py run
.\.venv\Scripts\python.exe main.py score workspace\submission.json agentic-bank-public\ground_truth.json
```

Готовый `submission.json` окажется в `workspace/`. Для приватного датасета
подмените `DATA_DIR` в `.env` — состав задачи читается из `submission_template.json`,
поэтому имена сценариев не хардкодятся.

## Тринадцать стадий

**0. Baseline submit.** Первая запись `submission.json` идёт сразу же — из шаблона
   заполняется каждой ячейкой с baseline-значениями. Дальше каждая успешно
   вычисленная ячейка её перезаписывает. Если прогон упадёт в середине — на диске
   остаётся валидный сабмит.

**1. Ledger map + gap scan.** Читаем `master_ledger_2025.csv` строго типизированно:
   пустые суммы остаются `NaN`, а не превращаются в 0. Список `TXN-*` с
   пропущенными суммами уходит на стадию 5.

**2. PDF extract с постраничным vision-фоллбэком.** PyMuPDF читает текст по
   страницам. Если страница даёт меньше 80 символов — мы отправляем её картинку
   в мультимодальный вызов Claude Sonnet и сохраняем ответ в
   `workspace/vision/{doc}_p{n}.txt`. На публичном сете это 7 страниц из 4-х
   документов. Кэш означает, что повторные прогоны и тесты не тратят API.

**3. Триаж с точечной нормализацией.** Регекс чинит только идентификаторы вида
   `A С С - 7 2 0 1` (пробелы и латиница/кириллица), обычный текст не трогает.
   Каждый документ получает тип-кандидат (`agreement/kyc/aup/audit_notes/noise`).
   Документы не удаляются: `noise` означает лишь «не входит в контекст стадии 6
   без специального retrieval».

**4. Граф версий.** Проекты, черновики и недействующие редакции остаются в
   графе как `rejected` — их существование бывает значимым (P10 6.1 требует
   отличать отклонённое от несуществующего). Разрешение по `superseded_by`,
   `effective_date`, `fiscal_year`.

**5. Targeted retrieval.** Для каждой транзакции с пропущенной суммой из
   стадии 1 ищем документ, где эта транзакция упомянута. Так подтягиваются
   служебная записка казначейства и приложение аудитора — их триаж отнёс к
   `noise`, но они содержат нужные `amount_correction`.

   Параллельно стадия 2 задачи «retrieval по имени материнской компании»:
   если ковенант упоминает «Группу»/«консолидированную отчётность», ищем в
   корпусе документ, где встречается имя заёмщика, и детерминированно
   достаём Group capex по формуле IFRS (end PPE − begin PPE + depreciation).

**6. Extract.** Один вызов на заёмщика на Haiku. Модель получает статью 6
   договора, аудиторские заметки, KYC и найденные на стадии 5 фрагменты.
   Возвращает `CovenantSpec`, `Adjustment`, `RelatedParty`, `DocumentFact` со
   ссылками и дословными цитатами. Числа не считает — только переносит.
   Детерминированные стражи проверяют оператор, наличие `max`/`applicability`
   /`exception` и присутствие порога в цитате.

   Поверх LLM-выхода накладываются два детерминированных патчера:
   - `lib/kyc_vision.py` — если threshold_percent пришёл `null`, парсит
     vision-текст KYC и восстанавливает порог связанных сторон и список долей.
   - `lib/consolidated_retrieval.py` — восстанавливает Group capex, когда
     ковенант ссылается на консолидированную отчётность родителя.

**7. Select.** Один вызов на заёмщика на Sonnet. Модель видит ковенанты,
   `role_descriptions`, отфильтрованные кодом связанные стороны и **срез
   ленты только этого сценария** (`TXN-{scenario_id}-*`). Возвращает
   исключительно идентификаторы транзакций по ролям — никаких сумм. Полный
   ledger используется только для валидации, чтобы поймать межсценарные
   галлюцинации.

**8. Compute.** Ограниченное дерево выражений (`sum/add/subtract/divide/max/
   min/const/fact`, глубина ≤ 4) исполняется на нормализованных к USD
   значениях. Facts из `document_facts` подставляются вместо `sum`, когда
   значение приходит из отчёта, а не из ленты.

**9. Evidence.** Только для `BREACH`. Ограниченный пул кандидатов
   (корректировки, boundary related-parties, валютные операции) и три
   контрфакта (drop, revert adjustment, flip related-party). Записываем
   ровно тот `txn_id`, чьё удаление возвращает в `COMPLIANT`.

**10. Validate.** Разделены `hard` (нарушение → ячейка не записывается, остаётся
    baseline) и `soft` (записывается, помечается `low_confidence`). Правило
    «hard» включает: конечное положительное `actual`, `status ∈
    {COMPLIANT, BREACH}`, `evidence_txn_id` существует в ленте.

**11. Verify.** Резервировано за перезапросом low-confidence ячеек к
    Haiku — заглушка. На публичном сете доля low-confidence < 15%, поэтому
    приоритет ниже, чем у стадий 1–10.

**12. Submit.** Атомарная запись `workspace/submission.json` после каждой
    успешно вычисленной ячейки: `NamedTemporaryFile` + `os.replace`. Одна
    сбойная ячейка не роняет прогон — ошибка попадает в
    `workspace/errors.log`, а сабмит остаётся полным и валидным.

## Обоснование ключевых решений

- **Workflow, а не автономный агент.** Поток управления в коде. Так проще
  воспроизвести, отладить и не тратить токены на «размышление о плане».
- **Никакого RAG, vector DB, LangGraph, fine-tuning.** Документы разделены
  чёткими маркерами (ACC-номер счёта, номер AR-отчёта, имя заёмщика).
  Детерминированный ретривал попадает точнее и быстрее.
- **Ни одно число не приходит от модели.** LLM возвращает только структуру
  и идентификаторы. Все суммы и коэффициенты считает Python. Это делает
  результат воспроизводимым и защищает от галлюцинаций в самых дорогих
  ячейках.
- **Модель Haiku для extract, Sonnet для select и vision.** На стадии 7
  Haiku теряет структуру при расширении контекста; Sonnet держит. Обе
  используются с prompt caching и (где возможно) с `temperature=0`.
- **Ledger виден селектору только по своему сценарию.** Предотвращает
  межсценарные галлюцинации при обогащённом extraction-контексте.

## Проверка результата

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe main.py score workspace\submission.json agentic-bank-public\ground_truth.json
```

## Лицензия PyMuPDF

Для извлечения текста используется PyMuPDF (AGPL-3.0). Для хакатона это
допустимо; перед использованием проекта вне его необходимо отдельно проверить
лицензионные условия.
